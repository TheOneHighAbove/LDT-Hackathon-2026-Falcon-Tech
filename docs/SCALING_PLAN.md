# План масштабирования static gallery до 1 000 000 изображений

## Текущий принцип

Release-пайплайн разделён на два этапа:

1. однократное извлечение признаков query и gallery;
2. поиск кандидатов и дорогой reranking только короткого списка.

Все межобъектные структуры строятся исключительно по static gallery. Поэтому
увеличение gallery не требует и не оправдывает совместную обработку test query.

## Индексация миллиона изображений

1. Gallery-кодировщик запускается асинхронно при добавлении или изменении
   изображения. Версия модели и SHA-256 весов сохраняются вместе с вектором.
2. Полный 1792-D float32 descriptor занимает около 6.68 GiB на миллион
   изображений; float16 — около 3.34 GiB. Для online-поиска используется
   OPQ/PQ-копия (например, 64–128 байт на изображение), а точные float16
   descriptors остаются для top-K reranking.
3. ANN-слой — шардированный FAISS IVF-PQ или HNSW. Шардирование выполняется по
   техническому hash ID, а не по предполагаемой identity или test query.
4. Из каждого шарда возвращается top-200/500; результаты объединяются в общий
   top-1000 по нормализованному cosine score.
5. Точные global descriptors пересчитывают top-1000, после чего текущие
   token/part/family reranker применяются только к top-50/top-25.

## Локальные признаки

Хранить полные DINO patch tokens для миллиона объектов в GPU-памяти нельзя.
Предлагается трёхуровневое хранение:

- global PQ-коды — в RAM каждого ANN-шарда;
- точные global float16 — memory-mapped на локальном NVMe;
- quantized part/patch features — в NVMe/object storage и подгружаются только
  для объединённого top-1000.

Популярные gallery-элементы и их локальные признаки кэшируются по LRU. Статические
gallery-neighbourhoods для family reranking вычисляются офлайн и версионируются.

## Обновления и консистентность

- новые записи сначала попадают в delta-index, затем пакетно сливаются в
  основной индекс;
- удаление выполняется через tombstone до следующей compaction;
- смена модели создаёт новый индекс рядом со старым, после проверки трафик
  переключается атомарно;
- metadata, descriptor и исходное изображение связываются immutable ID;
- мониторятся recall@K ANN относительно exact-подвыборки, latency p50/p95/p99,
  размер очереди и доля отказов.

## Ожидаемый online-путь

`decode/crop → три backbone → ANN top-1000 → exact top-50 → текущий reranker → refusal`

Целевой бюджет после извлечения признака: десятки миллисекунд на ANN и exact
rerank при GPU-индексе либо низкие сотни миллисекунд при CPU-шардах. Конкретные
SLA должны подтверждаться нагрузочным тестом на целевой инфраструктуре.

## Сохранение правил хакатона

- query обрабатываются независимо;
- индекс, граф соседей и PQ-кодбуки строятся только по static gallery;
- online query не записывается в gallery и не влияет на следующие запросы;
- camera ID и порядок query не являются признаками;
- open-set policy остаётся per-query и перекалибровывается при смене индекса.
